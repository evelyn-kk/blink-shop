# Blink Shop Android（用户端）

Java 原生，minSdk 24 / targetSdk 35。网络用 OkHttp，JSON 用系统自带的 `org.json`。

```bash
./gradlew test lint assembleDebug                 # 单测、静态检查、Debug APK
adb install -r app/build/outputs/apk/debug/app-debug.apk
```

## 代码结构

| 包 | 内容 |
| --- | --- |
| `net` | `ApiClient`（同步 JSON 请求）、`AuthInterceptor`（带 token、报告 401）、`ApiException`（错误分类和提示文字）、`SseClient`/`SseParser`（事件流）、`ApiConfig`（地址拼接与校验） |
| `model` | 接口数据（账户、会话、商品、规格、分类、评价、分页），金额和时间的显示格式 |
| `data` | `ShopApi`（用户端接口）、`SessionManager`（当前会话）、本地存储 |
| `ui` | 页面基类、后台调用、图片加载、加载/空/出错占位 |
| `catalog` / `account` / `settings` | 商品列表与详情、登录注册与账户、设置与帮助、调试版接口设置 |
| `cart` / `order` / `coupon` | 购物车与确认订单、支付/订单列表/详情/评价、领券与我的券 |

单测里的 `ShopApiContractTest`、`TradeContractTest` 直接读取 `backend/fixtures/http` 的接口样例：检查 App 发出的请求与样例一致、样例响应能正确解析。

## 服务地址

- Debug 默认 `http://10.0.2.2:8080/api/v1`（模拟器访问电脑本机）。真机或其他端口在 **登录页底部 / 我的账户 → 接口设置** 修改：可以先“测试连接”，保存后会退出登录（旧服务器的登录对新地址无效）。
- Release 没有修改入口，地址在构建时用环境变量 `BLINK_API_BASE` 注入，只允许 https。

## 权限

| 权限 | 用途 |
| --- | --- |
| `INTERNET` | 访问接口和图片 |
| `ACCESS_NETWORK_STATE` | 判断是否断网：断网时直接提示“网络未连接”，不发请求；网络恢复后列表自动重试 |

更换头像用系统图片选择器（`ACTION_GET_CONTENT`），不需要存储权限。相机、录音权限在聊天和语音功能（7.x/8.x）里再申请。

## 网络错误怎么提示

所有失败都转成 `ApiException`，界面只显示它的中文说明，不显示 Java 异常信息：

| 情况 | 提示 | 处理 |
| --- | --- | --- |
| 设备没网 | 网络未连接，请检查网络后重试 | 出错页带“重试”；列表在网络恢复时自动重新加载 |
| 地址写错、服务没启动、域名解析失败 | 无法连接服务器，请检查网络或服务地址 | 同上；调试版可去“接口设置”改地址 |
| 超时（连接 10 秒、读写 20 秒） | 请求超时，请稍后重试 | 重试 |
| 服务端返回错误 | 服务端的 `message`；有 `field` 时标在对应输入框上 | 按内容修改后重新提交 |
| 带 token 的请求返回 401 | 登录已失效，请重新登录 | 清除本地登录；需要登录的页面跳到登录页 |
| 429 | 请求过于频繁，请稍后再试 | — |
| 5xx 且不是 JSON | 服务暂时不可用，请稍后重试（状态码） | 重试 |

登录密码错误同样是 401，但请求没带 token，只提示“账号或密码错误”，不会当作登录失效。

## 会话

- 登录/注册成功后 token、过期时间和账户资料存在应用私有的 SharedPreferences（已关闭备份）。
- 冷启动时恢复会话：本地已过期的直接丢弃；否则后台请求一次 `/auth/me` 刷新资料，401 时清除。
- 退出登录先清本地，再在后台通知服务端撤销 token，离线也能退出。

## 交易

- 购物车、优惠、能否购买都以服务端为准：每次修改返回整个购物车；不可购买的原因（下架、售罄、数量超过库存）由服务端给出。修改请求串行，进行中忽略新的点击。
- 确认订单页展示服务端试算（与下单同一套计算），可选自动用券、不用券或自己选券；提交时带上页面显示的金额，金额变化时服务端拒绝并提示新金额，重新确认后再提交。
- **防重复下单**：每次提交把幂等键、用券选择和确认金额一起存到本地（`PendingCheckout`）后再发请求。结果未知（网络失败、超时、5xx、429、App 被杀）时这三样冻结：确认页提示上次提交没有结果，不能换券，只能“重新提交上次的订单”原样重发——上次如果已经成功，服务端返回那次的订单；如果没成功，就按上次的内容下单或被明确拒绝。拿到成功或明确拒绝（价格变化、购物车为空、券不可用等，说明没有下单）后才结束，下次提交是新的一单。提交时有遮罩挡住重复点击。
- 支付页按订单 ID 重新查询状态，App 被杀后重进不会重复支付；支付失败（含断网）后以服务端状态为准，未付的可以重新支付。
- 订单列表和详情每次回到页面都重新查询；取消、确认收货需要二次确认；评价内容随时存为本地草稿。
- 端到端脚本见 `e2e/README.md`。

## 旋转与后台

页面声明了 `configChanges`，旋转时不重建，列表位置、输入内容都保留。进程在后台被系统回收后，再回来时列表恢复搜索词和分类、详情恢复所选规格，登录页恢复登录/注册模式，然后重新加载数据。
