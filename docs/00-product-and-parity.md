# 产品范围与复刻口径

## 目标

交付一个可本地启动的多角色 AI 导购电商系统：Android 用户端负责导购到交易闭环；React Web 负责商家和平台运营；Go API 提供交易、Agent、检索、文件、治理能力。无模型密钥时，系统必须仍可运行并返回规则兜底结果。

## 角色与可见能力

| 角色 | 认证后能力 | 不得拥有的能力 |
| --- | --- | --- |
| user | 注册/资料、商品浏览、图片搜索、AI 会话、购物车、优惠券、下单、支付模拟、收货、评价、语音 | 商家和平台资源 |
| merchant | 自己商品 CRUD、商品知识入库、自己的订单发货、促销与评价回复 | 其他商家/所有用户数据 |
| admin | 账号/商家/商品风控状态、订单、促销、评价审核、Prompt、动态配置、向量状态、运行追踪、评测报表 | 明文查看密钥 |

## 必须等价的业务闭环

1. 商品目录：分类树、商家、关键词/分类筛选、详情、SKU、评价、促销。
2. 交易：购物车原子加购/改数量/选择，优惠试算，按商家拆单、锁库存、创建支付单、支付/取消/发货/收货/评价。
3. 导购：多轮会话、流式回答、商品卡片/比较/引用块、追问、取消运行、历史会话与运行 trace。
4. 多模态：上传文件、图片相似商品检索、图片附件触发 Agent 图搜；语音输入转写和 TTS 播放为可配置能力。
5. 运营治理：商家知识文档和非结构化采集、RAG、Prompt 版本发布、Nacos 动态配置、评测与风控。

## 明确不在第一版的范围

真实三方支付、物流对接、消息队列消费、分布式库存、推荐画像、iOS 原生端。支付使用受控的模拟状态迁移；Redis 和 Nacos 可降级，不应阻止本地开发。

## 复刻完成定义

- `docker compose up -d` 后，后端、Web 和 Android Debug 包均可按文档启动。
- 三个角色都有种子账号（账号与上游不同），能走通各自主流程。
- API 路径、状态码、JSON snake_case、SSE 事件类型与本文档一致。
- 模型、MinIO 或 Milvus 不可用时，有明示降级，不出现 500 或虚构商品。
- 所有关键授权、库存、幂等、敏感配置、上传校验均通过第 07 章测试门禁。
