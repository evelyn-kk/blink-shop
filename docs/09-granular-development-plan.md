# Blink Shop 细粒度开发计划

本计划按依赖关系排序。每个编号是一个可独立验收的功能包：完成该包的代码、接口契约、测试和交付物后再开始下一个。除明确标记为“可并行”的项外，后续包不得假设前置能力尚未实现。

## 全程规则

1. 先写 OpenAPI/请求响应 fixture，再实现服务端，再接 Web 或 Android；客户端不得自行补业务规则。
2. 每个功能包合入前必须：格式化、静态检查、对应单测、对应 HTTP 集成测试通过；改 API 时同时更新 OpenAPI 和 fixture。
3. 所有写接口必须有：身份校验、输入校验、资源归属校验、状态校验、错误码和审计日志。
4. 用户可见状态以服务端返回为准；金额使用十进制定点值；任何模型输出都不能直接执行写操作。
5. 每个功能包完成时提交一次，提交信息说明做了什么；通过远程 CI 后再进入下一个包。
